# Windows topology control recipe for review

This packet input instantiates the v0.2.91 broker and client design. Diagnostic status is **BLOCKED**. The readiness index must record the missing implementation and external evidence identified below. This artifact contains a source-level proposal and records no process observation.

## Roles and launch contract

The charged application roles are one broker, `L0_LEAF`, `L1_ROOT` and `L1_CHILD`. L0 finishes before L1 begins. The broker owns the direct launches and admits one delegated call by `L1_ROOT`. Each client is held at a release barrier. The delegated child starts normally and reaches its barrier after startup. [Frozen v0.2.91 contract](https://github.com/andaluzcoin/andaluzcoin/blob/1e40b1507ab2ffbd03a2d47d89bf009b9edd07a0/doc/andaluzcoin-auxpow-b-diagnostic-packet.md#L80-L149)

The manifest must bind exact absolute local paths `P` for the interpreter, `C` for the client source, `B` for the broker source, `W` for the working directory, `S` for scratch and `R` for the Windows system root. The supported host, token, session, local filesystem and PE subsystem are inputs. A version label or current workspace path supplies none of these identities. The candidate broker argument vector is `[P, '-I', '-S', '-B', B]`. Each client vector is `[P, '-I', '-S', '-B', C, '--role', ROLE]` with `ROLE` one of the three client roles. The client command line is `"P" -I -S -B "C" --role ROLE`, with the two full file paths substituted inside the quotes and frozen as exact UTF-16 code units. Reject a path containing a quote, NUL or terminal path separator. Packet, approval and attempt bindings arrive through a bounded `BOOT` frame on the private command pipe. This keeps the manifest digest out of its own command-line inputs.

Each client creation call uses `_winapi.CreateProcess(P, cmdline, None, None, True, flags, env, W, startupinfo)`. The explicit Unicode environment contains `SystemRoot=R`, `WINDIR=R`, `TEMP=S` and `TMP=S`. The reviewed runtime and loader closure must support this exact environment before it can be frozen. `STARTUPINFO` sets `dwFlags=0x00000101`, `wShowWindow=0`, and the three standard handles defined below. Its handle list contains those three distinct inheritable handles. The requested direct mask is `0x0000000c` and the effective mask `0x0008040c`. The requested delegated mask is `0` and the effective mask `0x00080400`. The pinned wrapper supplies the Unicode and extended startup bits. Freeze the launcher for the broker separately, including its startup and any pre-existing job or control plane. [CPython 3.9.0 wrapper](https://github.com/python/cpython/blob/v3.9.0/Modules/_winapi.c#L972-L1139) [Creation flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)

## Transport and ownership

Use three preconnected one-way byte pipes per client. Stdin carries broker commands, stdout carries framed client assertions and stderr carries bounded retained raw diagnostics. This selects the pipe option in the v0.2.90 recipe. In run-002, stdin was a NUL handle. Broker ends are noninheritable and overlapped. Client ends are synchronous and inheritable. Pipe names use the literal local `\\.\pipe\AndaluzTopo-<attempt-id>-<role>-<stream>` namespace, one instance, `FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS`, and an explicit DACL for the frozen launch identity. The broker opens both endpoints locally, confirms the connected opener is itself, then hands off the client end. Require successful setup and the expected endpoint access/direction before exposing an inheritable handle. The connected instance is single use. Buffer size requests are advisory kernel allocations. [v0.2.90 launch design](https://github.com/andaluzcoin/andaluzcoin/blob/63e92f435bf236848a083f9b98114f13a6603581/doc/andaluzcoin-auxpow-b-preparation-controls.md#L84-L122) [Named pipe creation](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-createnamedpipew) [Client PID](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeclientprocessid)

For a direct client the broker creates the process with only its three client ends and closes its copies after creation or confirmed failure. For the delegated client, the broker duplicates the three preconnected client ends into the already bound `L1_ROOT` process with `DUPLICATE_SAME_ACCESS` and inheritance enabled. The broker closes its copies. The root receives the target-process handle values on its private command pipe, uses those values once as its child's standard handles and handle list, and closes them on return from creation. The root's own std handles, job handles, process observation handles, I/O events and journal handles stay outside the child list. Private transport carries process-relative handle values only while needed. The durable receipt identifies them by ownership tokens. [DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle) [Handle-list attributes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)

Use an unsigned 32-bit little-endian length, followed by exactly that many bytes of the packet's canonical UTF-8 JSON. The proposed frame payload maximum is 4096 bytes. Freeze message keys, allowed state, byte and frame credits, and stream/role/session association in the quota and receipt artifacts. Each direction has one in-flight frame. Frame assembly may read partial I/O results within the same bound. A truncated frame, surplus frame, mismatched channel or unapproved extension causes refusal. An ACK binds attempt, packet, approval, case, role, generation, launch ID and the exact predecessor sequence/digest. A framed client assertion and a raw stderr byte are distinct evidence types.

## Sequencing and admission

The broker main thread is the sole sequencer and owns the state machine. Its charged blocking lane has one outstanding operation for file append/flush or direct process creation. The main thread submits the exact bytes or call and waits for the operation result before authorizing the next transition. It continues bounded pipe and deadline observation while the lane is busy. Native I/O and scheduling can delay both completion and cancellation. Freeze both threads, their stack and buffer ownership, lane completion rules and any trusted outer control explicitly. [Overlapped pipe I/O](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-server-using-overlapped-i-o) [Cancellation limits](https://learn.microsoft.com/en-us/windows/win32/fileio/canceling-pending-i-o-operations)

The broker appends the event envelope to a local exclusive append-only journal and requires a successful file flush before sending a grant that relies on it. It retains the observed append and flush result. An ACK pipe write completion alone supplies no proof that the client consumed the grant. The client checks the entire frame and later reports its bound predecessor. Use `FlushFileBuffers` for the journal only. Pipe draining follows the observed receive/exit protocol and bounded I/O completion, since flushing a server pipe can wait for its reader. [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)

1. For each direct call, persist `LAUNCH_INTENT`, `LAUNCH_AUTHORIZED` and the call-boundary `LAUNCH_ATTEMPT` in order. Release the blocking lane for one call only after the last durable acknowledgment. Record `LAUNCH_RESULT` from the actual return. A timeout during the call leaves entry or admission uncertain and consumes the attempt.
2. For a direct creation success, keep its returned process and primary-thread handles. Confirm PID and creation FILETIME through the process handle, image path and frozen disk identity, aggregate membership, successful assignment to the empty case job, and limits readback. Persist `PRE_RESUME_BOUND`. Call `ResumeThread` once and require previous suspend count `1`. Persist `RESUME_RESULT`, then send `BOOT` on the approved private channel.
3. For every client, accept `CLIENT_READY` only on the endpoint allocated to its lifetime. Corroborate PID and birth time through a still-held OS process handle. Bind the queried image to the frozen local file identity and require aggregate and case-job membership. Check the three std types and console observations under their own API semantics. Persist `IDENTITY_BOUND` and `RELEASE_ACK` for that exact READY. The recipient consumes one matching release grant and reaches the permitted next stage. A path, PID, process count or valid frame alone supplies insufficient identity.
4. After `L1_ROOT` is released, it sends one delegated intent assertion. The broker persists `LAUNCH_INTENT` then `LAUNCH_AUTHORIZED`, and sends the recipe and delegated handles. The root acknowledges that grant with a transport-only entry request. The broker persists `LAUNCH_ATTEMPT`, then sends the bound call permit. The root consumes the permit once and calls `CreateProcess` exactly once. Its result assertion carries the actual return, PID and creation FILETIME for success, or the documented error state. No root assertion is promoted to a broker OS observation.
5. On delegated success, the root retains the exact returned process handle. The broker duplicates that handle from the already held, bound root process with `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE`. It verifies PID, creation FILETIME, image and inherited membership, and records `LAUNCH_RESULT` with source provenance. Only then does it send the delegated child's `BOOT`. A compliant child's source waits for that frame before sending READY. An early frame is a sequencing failure. The child follows step 3. Root and broker retain their held process identities through child terminal and handle-signaled exit. The root receives the exact child-reconciled grant before its own terminal record and exit.
6. Observe each terminal frame, expected exit, stream EOF, outstanding I/O completion and job accounting before case completion. A reported exit code becomes final evidence after the process handle signals. Capture exit time only then. Close the owned thread/process/pipe handles and record closure separately. L0 must reconcile fully before the broker enters L1. The host artifact must establish provenance and protection against substitution across preflight, mapping and observations. Use a held process identity with `GetProcessId`, `GetProcessTimes`, `QueryFullProcessImageNameW` and `IsProcessInJob`. Add a direct client to its case job before resume and verify the delegated child inherits both memberships. Freeze process caps separately from expected role counts. A fresh empty job is not proof that the broker itself has an admissible parent job hierarchy. The host input must supply a reviewed startup/ownership boundary or leave readiness blocked. - Query the aggregate and nested job accounting and bounded PID lists. Record aggregate user/kernel 100 ns ticks as the charged total and child job numbers as attribution. ## Readiness blockers and review decisions

The broker-side delegated child handle has query and synchronization rights. If the child is outside its expected job, case-job termination cannot reach it. Review must establish exact owned-child termination rights or an exclusive guest fail-safe before launch. An unidentified helper requires separate ownership evidence.

The exact L1 recipe poses an admission problem. `L1_ROOT` is detached and has no parent console to pass to its normally started console-subsystem child. Microsoft documents that console applications normally initialize with a console. Explicit pipe handles and `SW_HIDE` provide no evidence of exclusive console-helper ownership. Windows build, console host delegation, helper identity/containment and lifetime network assurance must be resolved before L1 can be considered launchable. A GUI-subsystem image such as `pythonw.exe`, changed creation flags, a separate observation component or an admitted extra role would change the frozen experiment and needs an explicitly reviewed scope and evidence. [Console initialization](https://learn.microsoft.com/en-us/windows/console/allocconsole) [Console creation](https://learn.microsoft.com/en-us/windows/console/creation-of-a-console)

The pipe contract covers local IPC only. The broker, interpreter, children, OS-mediated helper paths, setup and cleanup still require independently established zero application network traffic across their required lifetime. The network-assurance artifact, exact host/loader closure, inactive broker/client sources, literal resource vector, receipt and expected-evidence artifacts, independent review and detached execution approval remain mandatory. The lowest-scope source preparation can freeze the pure frame parser, transcript state machine and offline refusal fixtures for review once the surrounding admission/network decisions agree. Native control implementation follows a coherent, separately scoped design. Operator budgets remain unselected, measurements on hold and mainnet NO-GO.
